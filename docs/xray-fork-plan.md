# План: свой форк Xray против ТСПУ (на потом)

Цель: изменить «почерк» трафика (а не протоколы), чтобы ТСПУ не узнавал ноды, и при этом
Remnawave продолжал управлять всем как сейчас.

## Принцип
- Меняем поведение тех же VLESS / Reality / XHTTP: отпечаток TLS, паддинг и размеры
  пакетов в начале соединения, тайминги, число и длительность соединений, ответ на
  активное зондирование. Панель проверяет только JSON-конфиг, внутреннее поведение не видит.
- Новые протоколы внутри Xray (TUIC, Mieru…) панель не пропустит — для них остаются
  наши шлюзы (server/titan-sbgw, server/titan-mieru-gw, MASQUE-шлюз).
- Изменённое поведение нужно с обеих сторон: в приложении и на ноде. Включать его только
  для отдельных инбаундов (признак в конфиге профиля, который панель не проверяет), чтобы
  Happ и другие клиенты на обычных инбаундах продолжали работать.

## Как собирать
- Форк как набор патчей поверх официального релиза Xray (как titan-sbgw для sing-box):
  CI накладывает патчи и собирает xray.exe (Windows), libXray (Android) и Linux-бинарник
  для нод вместо rw-core в ноде Remnawave.
- Подмену rw-core сначала пробуем на одной тестовой ноде (Латвия_1).

## Что нужно узнать перед кодом (у владельца)
1. Что перестаёт работать при «палеве»: весь IP ноды или один протокол/порт?
2. Как: соединение не устанавливается / зависает на первых ~15–20 КБ / режется скорость?
3. Какие протоколы чаще: Reality, XHTTP, Hysteria?
4. Через сколько: сразу, через дни, при росте числа пользователей?
5. Где: мобильный интернет, домашний, конкретные операторы?
Под ответы выбираем конкретные изменения.
