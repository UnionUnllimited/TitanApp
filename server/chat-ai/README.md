# ИИ в общем чате клиентов

Отдельный бот для Telegram-чата клиентов VPN. Отвечает на вопросы, ответ на
которые есть в базе поддержки (цены, тарифы, оплата, подключение), остальное
пропускает молча. Своего промпта у него нет, он берёт промпт бота поддержки.

## Откуда берёт знания

Из базы бота поддержки (`<папка поддержки>/data/vpn_support.db`):

- промпт из админки поддержки → AI. Если его там не меняли, берётся промпт
  по умолчанию из кода поддержки (`admin_web/ai_settings.py`);
- типовые ответы и тексты справочника (`PAY_*`, `VPN_*`, `BOT_*`) — то же,
  что получает ИИ поддержки;
- провайдер, ключ и модель, если в `.env` чата не задан `OPENAI_API_KEY`.

Сверху добавляется `extra.md` с дополнениями только для чата, например с ценами.

База открывается только на чтение и перечитывается раз в 30 секунд: промпт,
изменённый в админке, через полминуты действует и в чате. Бот поддержки
ничего не замечает, его код и база не меняются.

## Как решает, отвечать ли

1. Сообщение похоже на вопрос: есть «?» или слова «сколько», «как», «цена»,
   «тариф», «оплата» и т. п. Остальное до модели не доходит и ничего не стоит.
2. Пишет не админ чата и не оператор из `ADMIN_IDS`: им бот не мешает.
3. Это не ответ другому человеку: люди разговаривают между собой.
4. От одного человека не чаще раза в `USER_COOLDOWN` секунд.
5. Модель видит промпт поддержки и правило чата: отвечать, только если ответ
   есть в базе, иначе `SKIP`, и бот молчит. Вопросы про свою подписку и оплату
   уходят в бот поддержки (`SUPPORT_BOT_USERNAME`).

Если бота упомянули (`@бот`) или ответили на его сообщение, он отвечает и
без «?». Если человек комментирует пост канала, текст поста идёт в контекст.

Инструментов поддержки (данных о подписке клиента) в чате нет: бот не видит
чужие аккаунты и не может их раскрыть.

## Установка

Ставится на сервер бота поддержки, потому что ему нужна папка `data/`
поддержки.

1. В @BotFather: `/newbot`, получить токен. Затем `/setprivacy` → бот →
   **Disable**, иначе в группе бот видит только команды. Добавить бота в чат.

2. Код:

   ```bash
   git clone --depth 1 --filter=blob:none --sparse https://github.com/UnionUnllimited/TitanApp.git /opt/titanapp
   cd /opt/titanapp && git sparse-checkout set server/chat-ai && cd server/chat-ai
   ```

3. Настройки:

   ```bash
   cp env.example .env && nano .env
   ```

   `BOT_TOKEN` — токен нового бота. `SUPPORT_DIR` — папка бота поддержки.
   `BRAND_NAME`, `MAIN_BOT_USERNAME` и ссылки — как в `.env` поддержки.
   `SUPPORT_BOT_USERNAME` — бот поддержки.

4. Запуск:

   ```bash
   docker compose up -d --build && docker logs -f vpn-chat-ai
   ```

   В логе должна появиться строка `промпт: админка, … симв.; типовых ответов …;
   модель … ключ из админки поддержки`. Если вместо этого «не прочитал базу
   поддержки», проверьте `SUPPORT_DIR`.

5. Написать в чате `/chatid`: бот ответит id чата и ваш id. Вписать их в `.env`
   (`CHAT_IDS`, `ADMIN_IDS`) и перезапустить: `docker compose up -d`.

6. Проверка без чата: напишите боту в личку вопрос клиента. Он ответит так,
   как ответил бы в чате, или «SKIP: в чате бот промолчал бы». `/status`
   показывает, откуда взят промпт, какая модель и сколько запросов за час.

## Цены

Промпт поддержки часто не называет цены и отправляет клиента в бота. Чтобы чат
их называл, впишите тарифы в `extra.md` ниже комментария: для чата он важнее
промпта поддержки. Правки подхватываются за 30 секунд.

## Расход

Каждый запрос несёт промпт поддержки с базой знаний, это несколько тысяч
токенов. Начало запроса всегда одинаковое, и OpenAI берёт за повторы дешевле.
На gpt-4o-mini это доли цента за вопрос. Ограничители: `QUESTIONS_ONLY`,
`USER_COOLDOWN`, `MAX_CALLS_PER_HOUR`.

Свой ключ для чата (`OPENAI_API_KEY`) разделяет счета чата и поддержки. Если
ключ поддержки записан в её `.env`, а не в админке, его тоже нужно вписать сюда.

## Обновить и выключить

```bash
cd /opt/titanapp && git pull && cd server/chat-ai && docker compose up -d --build
docker compose stop      # выключить ИИ в чате
```
